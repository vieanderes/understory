# Architecture

Decisions with their reasons, as agreed in planning on 2026-09-17. Library sizes and Safari
behaviour noted here came from the planner's memory and are checked during the build.

Understory is web first, on Vercel now and self-hosted on Hetzner with Docker later. Nothing
may depend on a Vercel-only service. Desktop and mobile are equal targets. A native iOS app
follows and consumes the same content bundle and the same sync protocol, so content and
progress formats are language-agnostic.

## Decisions

| Core boundary             | `tsconfig.core.json` with `lib: ["ES2023"]`, no DOM and no node types. | Node version              | `.nvmrc` pins `24`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Active LTS and supported by Vercel. 22 is too old for a new repo.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Content format            | YAML with Markdown strings, validated by zod, compiled to JSON.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | YAML is the only option that gives iOS plain data. MDX and TS both need a JS toolchain to read.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| One course, no tracks     | Everything lives in `content/course/`: one `course.yaml`, one `outline.yaml` and one placement ladder, `content/placement.yaml`. The manifest holds `course` and `modules` directly, and lessons carry no track id. A new subject, such as Go, is a new module.                                                                                                                                                                                                                                                                                                                                                                                              | The subjects lean on each other: Python feeds the AI modules, system design draws on every chapter. Tracks split concepts, placement and ranks, and only one existed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Parts                     | `parts` in `course.yaml`: seven stretches of modules with a capstone each. The validator keeps every taught module in exactly one part, in outline order, and keeps woven modules out. The manifest and `catalog.json` carry each part's published lessons and concepts in journey order. Progress, the current part, the checkpoint session, time left and the milestone are derived in `src/core` (`insight/parts.ts`, `insight/time.ts`, `practice/checkpoint.ts`, `insight/milestone.ts`). A part id is one word that is not a module id, so `capstone_completed` and `test_out_attempted` name a part in their `moduleId` field with no new event type. | Near goals with their own progress line keep learners going better than one far goal (LEARNING-SCIENCE C, "Parts and milestones"). Deriving the milestone keeps law 3: nothing about it is stored, so a sync merge cannot award it twice. Reusing the two events kept the Swift reducer and the event contract unchanged.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Capstone ADRs             | A decision record is its own event, `capstone_adr_written` (v1) with `partId`, title, decision and optional context, alternatives and consequences, not new fields on `capstone_completed`. An edit is a newer event; the reducer keeps the latest per part in (at, deviceId, seq) order in `capstoneAdrs`, with the first and latest dates and the number of versions. `insight/adr.ts` derives the log and renders it to Markdown. `REDUCER_VERSION` is 2 on both platforms.                                                                                                                                                                               | An older client reads an unknown type as unknown and ignores it, but a strict schema would read a changed `capstone_completed` as unknown too and lose the capstone. Last writer wins without deleting anything, so a merge of two devices shows the same record and history is kept. No XP, so writing cannot be farmed.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Lesson layout             | Each lesson is a directory. `lesson.yaml` holds metadata and steps. `starter.ts`, `solution.ts` and `tests.ts` are sibling files that the compiler inlines.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Sibling files get linted and type-checked.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Markdown                  | A documented CommonMark subset with no raw HTML.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Swift `AttributedString` can render it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Step identity             | Every step has an explicit stable `id`, never an index. The validator checks ids are never reused.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Content edits cannot orphan progress.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Labs                      | A `lab` step requires a `fallback` step.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Clients that lack the widget still have a lesson.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Content bundle            | Static files, not route handlers. `scripts/build-content.ts` runs in `prebuild` and writes to `public/content/v1/` (gitignored). `manifest.json` is short-cached. Lessons are `lessons/<id>.<hash>.json` and immutable.                                                                                                                                                                                                                                                                                                                                                                                                                                      | Static files work on any CDN, can be cached by the service worker, and need no runtime for iOS.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Server access to content  | Server components import compiled objects through `src/lib/content` and never fetch them over HTTP.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | No network hop at build or render time.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Solutions and tests       | Reference solutions ship in separate lazy files. A playground's finished fields and a sql step's solution ship inside the lesson: short, and needed offline to judge an answer. "Hidden" tests are hidden in the interface only, and the docs say so.                                                                                                                                                                                                                                                                                                                                                                                                        | The bundle is public. Pretending otherwise would be dishonest.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Assessments               | A lesson with `assessment: true` is timed and scored on hidden correctness and performance tests, one sandbox run per test, isolated by a preamble that wraps the global `test`. Scores reach the log as ordinary `step_answered` events. The attempt's start time lives in sessionStorage.                                                                                                                                                                                                                                                                                                                                                                  | It rehearses the online tests learners face without a protocol change or a new event type. The hidden tests ship in the bundle like every test: hidden in the interface only.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Contracts                 | JSON Schema is emitted with `z.toJSONSchema` into `contracts/schemas/`. Golden fixtures live in `contracts/fixtures/`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | iOS Codable types and the Swift reducer are checked against the same files.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Sandbox page              | A real file, `/sandbox/runner.v1.html`, not `srcdoc`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `srcdoc` inherits the parent CSP.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Playground preview        | A `playground` step renders in an `<iframe sandbox="allow-scripts" srcdoc>`, with its own CSP `<meta>` (no network; scripts only when the step has `js`). A probe script posts check facts and the DOM tree; `evaluateChecks` in `src/core/playground` judges them. The content gate runs the same document and probe in jsdom. The solution ships inside the lesson.                                                                                                                                                                                                                                                                                        | A page must be drawn, so the worker runner does not fit. `srcdoc` needs no fetch and works offline; the opaque origin keeps the app safe. jsdom keeps `validate:content` fast with no browser; it has no layout, which checks avoid. A few lines of finished HTML are not worth a separate lazy file.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| React playground          | A `playground` with `jsx` renders the component with React 19 (development build) inlined in the same srcdoc frame. The parent transpiles with sucrase and fetches `/sandbox/react-playground.v1.js` once, both lazily. Checks may click and type first, each on a fresh render; the gate runs the same page in jsdom.                                                                                                                                                                                                                                                                                                                                       | Seeing a component render and respond is the point of the React chapter. Inlining keeps the frame free of any network, and the app CSP has no `unsafe-eval`. Fresh renders per check make grading deterministic and identical in the browser and the gate. The development build gives readable errors and key warnings.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Sandbox header            | `Content-Security-Policy: sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval' blob:; worker-src blob:; frame-ancestors 'self'` on the runner response.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | The `sandbox` directive forces an opaque origin even if an attacker opens the URL as a top-level page and posts code to it. Without it that code would run on the app origin with access to IndexedDB.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Offline runner            | The runner iframe has no `sandbox` attribute; the header's `sandbox allow-scripts` is its sandbox. The service worker answers the frame from its precached copy, headers included. Fail closed instead: the parent drops a frame it can read, the frame needs an opaque origin, the worker keeps no copy without the directive. Rejected: the attribute (no engine gives such a frame to the worker), a `blob:` runner (needs `frame-src blob:`, inherits the app CSP without `'unsafe-eval'`), `srcdoc`. Evidence: docs/SANDBOX.md, "Offline".                                                                                                              | Code runs offline behind the same wall: same header, flags and `default-src 'none'`. The attribute only repeated the header.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Sandbox protocol          | The parent sends `init` with a `MessageChannel` port, using `targetOrigin '*'` because the origin is opaque, and checks `event.source === iframe.contentWindow`. All later traffic goes over the port. Messages are zod-validated and carry `v` and `runId`. Logs are capped at 200 lines / 64 KB.                                                                                                                                                                                                                                                                                                                                                           | A narrow, versioned, validated channel.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Termination               | Two layers. The iframe calls `worker.terminate()` on timeout. A parent-side watchdog removes the iframe if no `done` message arrives.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | An infinite loop or a hostile runner cannot hang the tab.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Transpiling               | Sucrase, loaded with a lazy `import('sucrase')` in the parent, not inside the iframe.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | The same `Transpiler` adapter runs in Node, so CI and the browser behave identically.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

Tests may be `async def`: the harness's `run_async` is awaited on Pyodide's event loop. The Node gate loads the same wheels.                                                                                                                          | Interviews for AI roles ask for Pydantic, NumPy and pandas code, and async fan-out with a limit. ## Core API

```ts
// content
export const lessonSchema: z.ZodType<Lesson>;
type Step = ProseStep | PredictStep | /* ... */; // discriminant `type`

// grading
type Grade = { correct: boolean; score: number; feedback: FeedbackKey[] }; // score 0..1
gradeStep(step: Step, answer: Answer): Grade;          // pure; every type except code and DOM
gradeRun(step: CodeChallengeStep, result: RunResult): Grade;

// ports
interface CodeRunner { run(req: RunRequest, signal?: AbortSignal): Promise<RunResult> }
interface Transpiler { strip(src: string, lang: 'ts' | 'tsx' | 'js'): string }
interface EventStore { append(e: StoryEvent[]): Promise<void>; readAll(after?: Cursor): Promise<StoryEvent[]> }
interface SyncAdapter { push(e: StoryEvent[]): Promise<void>; pull(cursor: string | null): Promise<{ events: StoryEvent[]; cursor: string }> }
interface NewsStore { day(d: IsoDate): Promise<NewsDay | null>; range(from: IsoDate, to: IsoDate): Promise<NewsDay[]> }
interface Clock { now(): Date }
interface IdGen { next(): string }

// scheduling
schedule(card: CardState | null, rating: Rating, now: Date): CardState;
dueCards(state: ProgressState, now: Date): CardId[];

// progress
upcast(raw: unknown): StoryEvent | UnknownEvent;
reduce(events: readonly StoryEvent[]): ProgressState;   // sorts by (at, deviceId, seq); order-insensitive

// gamification
xpFor(e: StoryEvent, ctx: RuleCtx): number;
rankFor(mastery: MasteryStates, capstones: number, calibration: number): Rank;
applyWeek(state: WeekState, xp: number): WeekState;

// practice
buildSession(state: ProgressState, catalog: Catalog, now: Date, size: number, rng: Rng): SessionItem[];

// news
normalise(raw: RawItem): NewsItem;
dedupe(items: NewsItem[]): NewsItem[];
score(item: NewsItem, profile: Interests, now: Date): number;
```

The planner's sketch had `levelFor` and `streakOf`. The learning design replaced levels with
ranks and streaks with a weekly goal, so the gamification signatures above follow
`LEARNING-SCIENCE.md` section C.

## Top risks

| #   | Risk                                            | Mitigation                                                                                                                                                                       |
| --- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Safari storage eviction wipes progress.         | Call `persist()`, prompt for export, push the installed PWA, and bring sync forward if it bites.                                                                                 |
| 2   | Sandbox escape or tab freeze.                   | The `sandbox` CSP header, the two-layer kill and HTML/CSS-only DOM challenges in v1. WebKit e2e on top. Blob-URL workers in an opaque origin on Safari are verified in M4.       |
| 3   | Bundle size.                                    | CodeMirror with hand-picked extensions, loaded on the first code step. Sucrase loads lazily on the first TS run. No framer-motion. Budgets below, enforced by a Playwright test. |
| 4   | Mobile performance.                             | Server-side highlighting and static pages. Targets below.                                                                                                                        |
| 5   | Content drift breaks progress.                  | Stable step ids, `contentRev` on every event, an ids-never-reused check in the validator, and orphaned events ignored.                                                           |
| 6   | Go, Swift and Kotlin cannot run in the browser. | `RunRequest.language` plus a remote-runner adapter later. Those modules lean on non-execution step types. Python runs through Pyodide (SANDBOX.md).                              |
| 7   | News quality and legal exposure.                | Summarise only the supplied text, link sources, cap items, validate the schema and store no article bodies.                                                                      |
| 8   | Scope. Twelve and more step types is a lot.     | M3 ships six: prose, predict, multiple-choice, fill-blank, parsons and recall. The rest are added one per commit behind the union.                                               |

## Performance budgets

| Budget                                      | Limit          |
| ------------------------------------------- | -------------- |
| Lesson route JS without the editor, gzipped | 130 KB or less |
| Editor chunk, gzipped                       | 180 KB or less |
| Transpiler chunk, gzipped                   | 80 KB or less  |
| LCP on a mid-range phone over 4G            | under 2.0 s    |
| INP                                         | under 200 ms   |
| CLS                                         | under 0.05     |

A Playwright test sums transferred JS per route and enforces the JS budgets, which works with
any bundler.

## Milestones

Each milestone ends with `pnpm check` and e2e green. The full table, including content waves
and review passes, is in the approved plan. The engineering sequence from the architecture
review is below.

- **M0 Skeleton.** Repo, configs, CI, dependabot, the core boundary lint, tokens and the
  no-arbitrary-values test, an empty home page, e2e smoke on desktop and WebKit with an axe
  check, docs stubs. Tests written after.
- **M1 Content pipeline.** Schema, fs readers, validator, compiler and manifest, JSON Schema
  emit and two sample lessons. Strict TDD, including `CONTENT_ROOT` broken-copy tests.
- **M2 Progress core.** Events, upcasters, reducer, gamification, and the scheduling wrapper
  with a fake `Clock`. Golden fixtures written to `contracts/fixtures`. Strict TDD.
- **M3 Lesson player, non-code steps.** Pure graders under TDD; components tested after with
  Testing Library. idb adapter with its contract suite, plus export and import.
- **M4 Sandbox.** Runner page and header, protocol, and `NodeWorkerRunner`. The
  reference-passes / starter-fails CI gate. Protocol and harness under TDD. E2e tests for
  infinite loop, log flood and top-level-open attacks.
- **M5 Editor.** Lazy CodeMirror with a symbol bar. `code-challenge`, `bug-hunt` and
  `ai-review` steps. The bundle-budget e2e test. Tests written after.
- **M6 Practice.** `buildSession` under TDD with a seeded RNG. Review UI, weekly goal and XP
  surfaces.
- **M7 Signal.** `normalise`, `dedupe` and `score` under TDD, with recorded fixtures and no
  network in tests. CLI, workflow and pages.
- **M8 onwards.** Labs, incident desk, comprehension coverage, PWA, DOM challenges,
  self-hosting and the iOS package, as listed in the approved plan.
